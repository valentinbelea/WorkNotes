# Planificare WorkNotes

Documentele de planificare adună, într-un singur loc, ce este aplicația, ce s-a construit până acum (version_0.01), de ce s-a ales fiecare soluție și ce urmează. Sunt documente de lucru: se actualizează la fiecare pas nou.

| Fișier | Conținut |
| --- | --- |
| [01-viziune-si-domeniu.md](01-viziune-si-domeniu.md) | Scopul aplicației, conceptele de bază (context, jurnal, articol, paragraf, referință) și principiile de lucru |
| [02-model-de-date.md](02-model-de-date.md) | Tabelele existente, regulile paragrafelor, tabelele planificate și scripturile SQL |
| [03-arhitectura.md](03-arhitectura.md) | Straturile soluției, fluxurile principale, paginile, componentele și scripturile JavaScript |
| [04-functionalitati-realizate.md](04-functionalitati-realizate.md) | Pașii realizați, în ordine, cu comportamentul rezultat |
| [05-decizii.md](05-decizii.md) | Jurnalul deciziilor, cu motivele lor |
| [06-backlog.md](06-backlog.md) | Ce urmează: pașii rămași din plan, întrebări deschise, limitări cunoscute |

Documente de referință, păstrate separat:

- [../../AGENTS.md](../../AGENTS.md): regulile obligatorii (arhitectură, Database First, localizare, design, Git);
- [../design-system.md](../design-system.md): ghidul vizual și contractul componentelor;
- [../../README.md](../../README.md): pornire, configurare, scripturi și un rezumat al funcționalităților.

Regula de întreținere: la fiecare pas nou se completează 04 (ce s-a făcut), 05 (deciziile noi) și 06 (ce s-a închis sau a apărut), iar 02 și 03 când se schimbă schema sau structura.
